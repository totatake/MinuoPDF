# ADR-0002: CTM 実効 DPI・Smart Fallback・インメモリ PDF Audit パイプライン

- **ステータス**: Accepted
- **日付**: 2026-10-17
- **関連文書**: [システムアーキテクチャ](../architecture.md), [バックエンド詳細設計](../design/backend.md)

## 1. 背景と課題 (Context)

単純な「全画像の一律リサイズ＆JPEG 再圧縮」では、PDF 最適化時に以下の品質・サイズ劣化問題が発生する。

1. **実効 DPI の誤判定**: 高解像度画像でもページ上で小さく配置されている場合と大きく配置されている場合で必要なピクセル数が異なる。
2. **Form XObject / SMask の不整合**: `/Subtype /Form` 内にネストされた画像の取りこぼしや、親画像のみリサイズして透過マスク（`SMask`）の寸法が食い違う破損リスクがある。
3. **逆圧縮（サイズ肥大化）**: すでに最適化済みの画像を無変換で再エンコードすると、かえってバイト数が増えることがある。
4. **PDF Audit の二重ディスク I/O**: 最適化前後の内訳解析のために PDF を再度ディスクからロードし直すと、大容量 PDF で不要な遅延が生じる。

## 2. 決定 (Decision)

`src-tauri/src/optimizer.rs`（`DES_BE_001`）および `src-tauri/src/audit.rs`（`DES_BE_AUDIT`）において以下を統合パイプラインとして採用する。

1. **CTM 実効 DPI 算出**: コンテンツストリームの `cm` / `Do` オペレータを解析し、ページ上の実効表示サイズ（pt）から目標リサイズ解像度を決定する。
2. **Form XObject 再帰走査 & SMask 同期**: `/Subtype /Form` を再帰走査し、親画像リサイズ時は対応する `SMask` も同一比率でリサイズする。
3. **Smart Fallback ガード**: リサイズやカラー変換を行わない画像で再エンコード結果が元ストリームより肥大化する場合は、元ストリームをそのまま保持する。
4. **Rayon 並列処理**: 抽出した `ImageTask` 群のデコード・リサイズ・再エンコードを `into_par_iter()` で並列実行する。
5. **インメモリ共有 Document 監査**: `lopdf::Document::load` した単一オブジェクトおよび `save_to` 直前の保持状態に対して `audit_document` を呼び出し、ディスク再読込ゼロで変換前後の `PdfAuditComparison` を生成する。

## 3. 結果と影響 (Consequences)

- **良い影響**: 画像品質・透過マスク整合性を保ちつつ逆圧縮を防ぎ、GUI/CLI の大容量 PDF 処理スループットと Audit 応答性を両立できる。
- **受け入れるトレードオフ**: コンテンツストリームの CTM オペレータ異常入力に対する堅牢なパーサ維持が必要（`v0.2.1` にて演算子パース堅牢化を実施）。
